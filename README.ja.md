## まず聞いてください：3つの賛歌を、リズムに合わせて歌います

**[アメイジング・グレイス、美しいアメリカ、共和国の戦いの歌](https://mcp-tool-shop-org.github.io/ai-jam-sessions/#listen)**。
各賛歌のために書かれたピアノ伴奏に合わせて、合成音声で各節を歌う。ランディングページでは、3Dの楽譜が音声と歌詞に合わせて表示され、歌詞が歌われると光る。

各演奏は、楽譜に基づいて調整されたボーカルの16テイクから構成されています。
- 各フレーズにつき1テイクで、ローカルのリスナーとピッチトラッカーによって選択されます。
- 時間調整を行い、楽譜上に配置することで、フレーズ内の部分が途切れることがありません。
- 2つのタイミング測定器と2つのピッチトラッカーによってチェックされます。
- 最終的に、聴覚による確認が行われ、問題があれば、その原因まで遡ってレビューに記録されます。

各曲の前に、音声チェックを行い、音声のタイミングの特性を測定し、その曲に必要なテイク数を決定します。

どのように作成されたか：[ハンドブック → ボーカル](https://mcp-tool-shop-org.github.io/ai-jam-sessions/handbook/vocals/)。

| | Amazing Grace | America the Beautiful | Battle Hymn |
|---|---|---|---|
| 楽譜から40ミリ秒以内の音節 | 107/112 | 217/224 | 285/414 |
| 50セント以内の音 | 135/140 | 218/224 | 368/424 |

Battle Hymnの速い付点音符は、歌手自身のタイミングで演奏されるため、タイミングのずれが生じやすい。

音声は合成音声：[SoulX-Singer](https://github.com/Soul-AILab/SoulX-Singer)（Apache-2.0）。独自の音色サンプルを持ち、実際の歌手を模倣していない。ピアノ伴奏は、このプロジェクトのためにKimi-K3が作曲し、パブリックドメインに提供する（CC0）。3つの賛歌はいずれもパブリックドメインである。

## これは何ですか？

AIが演奏を学習するピアノとギターです。シンセサイザーでも、MIDIライブラリでもありません。これは、AIに音楽を教えるための楽器です。

LLMはテキストを読み書きできますが、私たちが音楽を体験するのと同じようには体験できません。耳もなければ、指もなければ、筋肉の記憶もありません。AI Jam Sessionsは、モデルが実際に使用できる感覚を与えることで、このギャップを埋めます。

- **楽譜の読み取り** — 詳細な音楽注釈が付いた実際のMIDI楽譜。手書きの近似ではなく、解析、分析、説明を行う。
- **聴覚** — 6つのオーディオエンジン（オシレーターピアノ、サンプルピアノ、ボーカルサンプル、物理的なボーカルトラクト、加算型ボーカルシンセ、物理的にモデル化されたギター）がスピーカーを通して再生され、部屋にいる人々がAIの「耳」となる。そして今、このモデルは独自の「耳」を持つようになった。録音を後から評価できる（[リスニング](#試聴)を参照）し、音楽が流れている間（[ライブアンサンブル](#ライブアンサンブル)を参照）に演奏を観察できる。
- **視覚** — ピアノロールは、再生された内容をSVGとしてレンダリングし、モデルが読み込んで検証できる。インタラクティブなギタータブ譜エディター。視覚的なキーボード、デュアルモードのノートエディター、チューニングラボを備えたブラウザのコントロールパネル。
- **記憶** — セッション間で永続化される練習ジャーナル。これにより、学習が時間とともに蓄積される。
- **歌唱** — 20種類の音声プリセットを備えたボーカルトラクト合成。オペラ歌手からエレクトロニックコーラスまで。ソルフェージュ、音程、音節によるナレーションを備えた、一緒に歌えるモード。そして、ピアノのテンポに合わせて歌われる楽曲全体。楽曲の構成に基づいて、多くのテイクからフレーズごとに組み立てられ、タイミング（40ms）と音程（50セント）で調整された後、聴くことができる（[歌唱](#歌う)を参照）。

現在、109曲すべてに完全な注釈が加えられています。歴史的背景、小節ごとの構造分析、重要なポイント、教育目標、パフォーマンスのヒントなど、すべての12のジャンルについて。このREADMEの以前のバージョンでは、生の楽曲は「AIがパターンを吸収し、音楽を演奏し、独自の注釈を作成するのを待っている」と記載されていました。まさにそれが起こりました。注釈は、決定論的な楽曲ごとの分析（コード、反復構造、セクションの境界、コンテンツが検証されたキー）に基づいてAIによって作成され、品質基準によってゲート処理され、そして、主張ごとに反対意見による事実確認が行われました。測定番号、コードウィンドウ、構造カウントはすべて、実際のMIDIに対して検証された後に出力されました。

このプロジェクトから、**[jam-actions-v0](#トレーニングデータセット)** — 実際のクラシックピアノの57のマルチターンMCPツール使用のデータセットも公開する。これは、単なるテキスト生成ではなく、シンボリックな音楽における*具体的なツール使用*をLLMに教えるものであり、7軸のリリースゲートが付属しており、「証拠を伝える」ことと「タスクが些細であるために合格する」ことを区別する。詳細については、以下の[トレーニングデータセット](#トレーニングデータセット)を参照。

## 試聴

以前は、このサーバーは音を出すことはできましたが、分析することはできませんでした。モデルが演奏し、人がそれを聞き、モデルはその人の意見を尊重していました。しかし、そのギャップは今や解消されました。

WAVファイルを指定すると、その内容を測定します。楽譜に対して現在使用しているのと同じ種類のツールを使用して信号を処理することで、画像を見て推測するのではなく、測定を行います。

- **`analyze_audio`** — 音の開始点、音程の輪郭、レベル。音程は、セント単位のずれとともに、音名として返される。生の周波数としては返されない。レベルとは、BS.1770-4に準拠したLUFS単位の統合ラウドネス、dBFS単位のサンプルピーク、クリップされたサンプルの数、およびドロップアウトやノイズバーストを報告する整合性チェックである。これは、レンダリングの品質管理における「クリックとグリッチ」の側面である。バランスセクションでは、サブベースから高音域まで、各帯域のエネルギーがピンクノイズに対してどの程度であるか、明るさ、傾きを示す。
- **`transcribe_audio`** — 録音を音符として表現：音程、開始時間、持続時間、および各音符がコンサートピッチからどれだけ離れているか。
- **`score_audio_take`** — ライブラリ内の楽曲を**耳で**評価して、演奏の質を評価する。録音をトランスクライブし、楽譜と照合し、どの音符が正確に演奏され、どの音符がずれて演奏され、どの音符が演奏されなかったかを報告する。その後、`view_scored_piano_roll`がその結果を楽譜上に描画し、キャプチャされたMIDIテイクと同様に表示する。これにより、実際の楽器、歌唱テイク、またはMIDIをキャプチャできないものを評価できる。
- **`view_spectrogram`** — 音を視覚化する。ピアノのキーボードが左端に配置された定Qスペクトログラム。これにより、音程が一目でわかる。必要に応じて、楽曲の意図された音符がその上に描画される。
- **`check_loop_seam`** — ループ再生を評価する。波形のステップは、テイルの傾きを外挿した後、結合部にバースト状のエネルギー、およびシームにわたるレベルシフトを評価する。位相が完全に一致したループは、生の境界サンプルがジャンプしても、きれいに聞こえる。
- **`compare_balance`** — 既知の正しい参照に対して、レンダリングの音色をバンドごとにdBで評価する。キューは、他の音と同様に聞こえるはずであり、再レンダリングは、置き換えるテイクと一致するはずである。ラウドネスは相殺されるため、音色のみが比較される。

**このツールではわからないこと。** 画像は、*どこ*に問題があるかを見つけるためのものである。すべての数値は、信号処理から得られるものであり、モデルが画像を読み取って得られるものではない。トランスクライバーは一度に1行を処理するため、コードやフルミックスでは、確信を持って誤った結果が出力され、その旨も表示される。音の開始点の検出精度は、最先端技術で約F10.88であるため、「見逃された」音符は、実際に演奏されなかったのではなく、トランスクライバーが聞き取れなかったものである可能性がある。これらのツールは、その点に注意を払い、出力にその情報を表示する。

全体的な構造は、依存関係がありません。変換、ピッチトラッカー、発音検出器、WAVデコーダー、PNGエンコーダーはすべてこのリポジトリにあり、Nodeとブラウザの両方で同じ数値を生成します。

## ライブ・アンサンブル

試聴機能は、録音を完了した後に評価します。これは、その逆の機能です。演奏中に、各楽器が**現在**何をしているかを尋ねます。

```
ensemble_now()
```

各楽器の持続音、その持続時間、およびアンサンブル全体のコードを返します。デュエットの場合、2つの音声は個別に報告されるため、ピアノが三和音を保持し、シンセがその上にメロディーを演奏している様子を確認できます。

### 2つのチャンネルがあり、安価な方が正確です

これは理解しておくべき部分であり、どの数値を信頼するかを決定します。

**意図 - 各エンジンに演奏するように指示されたこと。**モデルが演奏する場合、これは推定ではありません。ピアノのコードは、トランスクライブするものではなく、送信された3つのノートオンです。ノートは正確で、自由で、即時です。

**音響 - 実際にどのような音が鳴ったか。**各エンジンは、出力をプライベートな分析バスに送ることができるため、すべての楽器は、分離や曖昧さなしに、ソースで測定されます。このチャンネルは、**発見ではなく検証**です。これにより、音声がタイミングからずれたり、録音が途切れたり、エンジンがノートを送信され続けているにもかかわらず沈黙したりしたことを知ることができます。

2つの結果が一致しない場合、それはレンダリングに関する事実であり、ノートの修正ではありません。

### コスト

楽器を監視するには、42.67msのブロックに対して、約**9マイクロ秒/オーディオコールバック**かかり、これはオーディオバジェットの約0.02%であり、サンプルが1つもドロップしていない状態で測定されます。オブザーバーがアタッチされていない楽器は、まったくコストがかかりません。

### ただし、以下のことはわかりません

音響チャンネルは遅れており、その遅延量を示します。約23ms（ピッチ）、および70ms（確認された発音）です。これは、その後のオーディオが到着するまで、発音を確認できないためです。そのエッジに近い発音は、報告されてから後で取り下げられるのではなく、保留されます。

音響トラッカーは一度に1行を追跡するため、コードのノートを特定することはできません。また、そうしようともしません。解決できないコードは、既知の制限であり、アンサンブルは、ピアノが演奏するすべてのコードで「狼少年」のように叫ぶのではなく、静かにします。

## ピアノロール

ピアノロールは、AIが音楽をどのように認識するかを示します。AIは、あらゆる曲をSVG形式でレンダリングします。右手の音は青色、左手の音はコーラル色で表示され、ビートグリッド、ダイナミクス、小節の境界線も表示されます。

## コックピット

このリポジトリにあるブラウザベースの作曲スタジオ：[`apps/cockpit`](apps/cockpit)。また、**[mcp-tool-shop-org.github.io/ai-jam-sessions/cockpit](https://mcp-tool-shop-org.github.io/ai-jam-sessions/cockpit/)**でライブで実行できる。プラグイン、DAW、インストールは不要。すべてがブラウザ内に保存される（作業はローカルに自動保存される）。ハッキングしたい場合は？

```bash
cd apps/cockpit && npm install && npm run dev   # Vite dev server, opens in your browser
```

- **デフォルトではサンプリングされたコンサートグランドピアノ** — コックピットには、トリミングされたサラマンダーグランドパック（90個のOGGファイル、8MB）が同梱されており、初回起動時にロードされ、シンセサイザーのボイスと同じ出力チェーンを通じて再生されます。ロードされる前（またはオフライン時）には、調整されたオシレーターピアノがシームレスにカバーします。サンプルは[Alexander Holm](https://freepats.zenvoid.org/Piano/acoustic-grand-piano.html)によるもので、CC-BY 3.0です。
- **パネルモード — リスニングルーム** — 実際のライブラリのメロディーを基にした、作曲エンジンのボイシングのブラインドペアワイズA/Bオーディション：音量調整されたクリップを、実際のボイスパスを通じてオフラインでレンダリングし、隠された下限のトライアルを含む、シャッフルされたトライアルを生成し、ブートストラップ信頼区間を使用したブラッドリー・テリーランキングを行い、正直な結果を出力します（すべてのペアが投票予算に達するまで一時的な結果、識別閾値が失敗した場合は解釈不能）。2番目のサブモードでは、ローカルLLMジャッジを使用して同じランキングを実行し、さらに両方の実行タイプにわたる履歴と、比較ビュー（ケンダルτ + エンジンランクマッチ）を提供します。これは、安価なプロキシトラックが人間の真実をどれだけ追跡しているかを尋ねます。
- **正確なビートに同期したトランスポート** — ノートは音楽の時間軸に沿って再生されるため、BPMコントロールは実際に再生時間を調整します。ドラッグしてループ領域を設定できる、クリックしてシークするタイムルーラー。プレイヘッドを追跡する自動スクロール。
- **録音アームキャプチャ** — QWERTYキー、オン スクリーンキーボード、またはWeb MIDIデバイスを操作すると、スコアに記録されます。1小節のカウントイン、ループサイクル全体にわたるルーパースタイルのオーバーダビング（または置換モード）、量子化されたビューの下で生のパフォーマンスタイミングを保持し、各パスは1つの元に戻せる単位として扱われます。
- **完全な元に戻し/やり直し** — クリアやインポートを含むすべての編集は元に戻すことができます（Ctrl+Z）。ドラッグジェスチャーは、実際の編集ツールと同様に統合されます。
- **複数選択 + クリップボード** — 選択/描画ツールの切り替えの下で、長方形選択を実行します。プラットフォーム標準の修飾キークリック、プレイヘッドでのコピー/カット/ペースト、複製。
- **タッチ + アクセシビリティ** — すべてのサーフェスでキャプチャされたポインターイベント、ドラッグ以外の代替手段としてタップして再配置、キーボードによるノート編集、色覚異常でも識別しやすいスコアオーバーレイ。
- **デュアルモードピアノロール** — インストルメントモード（クロマチックピッチクラスの色）とボイスモード（母音の形によって色が付けられたノート：/a/ /e/ /i/ /o/ /u/）を切り替えます。
- **ビジュアルキーボード** — C4から2オクターブをマッピングし、QWERTYキーボードに割り当てます。クリックまたは入力します。
- **20個のボイスプリセット** — 15個のKokoroマッピングされたボイス（Aoede、Heart、Jessica、Sky、Eric、Fenrir、Liam、Onyx、Alice、Emma、Isabella、George、Lewis、および合唱とシンセボイス）、4個のトラクトマッピングされたボイス、および合成合唱セクション。
- **10個のインストルメントプリセット** — サーバー側の6つのピアノボイスに加えて、シンセパッド、オルガン、ベル、ストリングス。
- **ノートインスペクター** — 任意のノートをクリックして、ベロシティ、母音、ブレス音を編集します。
- **7つのチューニングシステム** — 平均律、純正律（長調/短調）、ピタゴラス音階、四分音平均律、ヴェルクマイスターIII、またはカスタムセントオフセット。調整可能なA4基準（392〜494 Hz）。
- **チューニング監査** — 周波数テーブル、ビート周波数分析を備えたインターバルトエスター、およびチューニングのエクスポート/インポート。
- **スコアのインポート/エクスポート** — スコア全体をJSONとしてシリアライズし、ロードします。
- **LLM対応API** — `window.__cockpit`は、`exportScore()`、`importScore()`、`addNote()`、`play()`、`stop()`、`panic()`、`setMode()`、および`getScore()`を公開するため、LLMはプログラム的に作曲、編曲、および再生できます。

## 曲のライブラリ

12のジャンルにわたる109曲のアノテーション付き楽曲。実際のMIDIファイルから作成されています。各ジャンルには、歴史的背景、小節ごとのハーモニー分析、重要な瞬間、教育目標、およびパフォーマンスのヒント（ボーカルガイダンスを含む）を備えた、深くアノテーションされた模範曲が1つあります。これらの模範曲はテンプレートとして機能します。AIはまず1つを学習し、次に残りの曲にアノテーションを付けます。フォークの模範曲は、「アメリカの美しい」（Samuel A. Ward、1882年、パブリックドメイン）で、このリポジトリでアレンジされたF長調の賛美歌で、メロディーはF4–C5です。

**同梱されるものと、取得するもの。** アノテーションは当社のもので、すべての曲に同梱されています。MIDIファイルは、ライブラリが作成されたときに、パブリックMIDIサイトからダウンロードされました。ファイルごとの出所監査（[`docs/findings/library-provenance-audit.md`](docs/findings/library-provenance-audit.md)）の結果、再配布を許可するライセンスを持つダウンロードは14個のみであることがわかりました。これには、Bernd Kruegerのpiano-midi.deの編曲（CC-BY-SA-3.0-DE）と、Mutopia Projectのパブリックドメインのタイプセットが含まれます。これらの14個はnpmパッケージに含まれています。残りの94個のダウンロードは含まれていません。それらの`.json`は、ソース、その条件、およびファイルのSHA-256を記載した`provenance`ブロックとともに同梱され、`ai-jam-sessions library fetch --accept-source-terms`は各ファイルを、そのサイトの条件の下で、そのサイトからダウンロードし、アノテーションが検証されたものと一致しないハッシュ値を持つファイルを拒否します。名前が実際の曲と異なることが判明した12個のファイルは隔離されました。そのため、ダウンロードされたライブラリには108曲であり、以前のバージョンで主張されていた120曲ではありません。「アメリカの美しい」は109番目の曲であり、パッケージに同梱されている15番目のMIDIファイルです。このアレンジはここで作成され、パブリックドメインに寄贈されました。バージョン2.6.0より前のバージョンでは、すべての120個のMIDIファイルが同梱されていました。これは間違いであり、ここで修正され、後で修正されることはありません。

## 練習日誌

各セッションの後、サーバーは、どの曲、どの速度、何小節、どれくらいの時間演奏したかを記録します。AIは、何に気づいたか、どのようなパターンを認識したか、次に何を試すべきかを自身の考察として追加します。

```markdown
---
### 14:32 — Autumn Leaves
**jazz** | intermediate | G minor | 69 BPM × 0.7 | 32/32 measures | 45s

The ii-V-I in bars 5-8 (Cm7-F7-BbMaj7) is the same gravity as the V-i
in The Thrill Is Gone, just in major. Blues and jazz share more than the
genre labels suggest.

Next: try at full speed. Compare the Ipanema bridge modulation with this.
---
```

1日に1つのマークダウンファイルとして、`~/.ai-jam-sessions/journal/`に保存されます。人間が読める形式で、追記のみが可能です。次のセッションでは、AIはその日誌を読み、中断したところから再開します。

### 音響コーパス

**jam-actions-acoustic-v0** — 上記のトレースに対応するもので、シンボリック音楽ではなく、**オーディオ**を対象としています。72件のレコードがあり、それぞれが、公開ドメインのフレーズの意図的に変更された合成レンダリングと、分析ツールが実際に返す結果をペアにしています。そのため、すべてのラベルは、それ自体だけでなく、楽器に対して検証されます。

| | |
|---|---|
| バージョン | 1.1.0（2026年9月25日）— 1.0.xの36件の「Träumerei」レコードを削除しました。これらのレコードのソースファイルには、確立された編曲ライセンスがありません。 |
| レコード | 72 — 2つのフレーズ（バッハ、エリーゼのために）× 9種類の摂動 × 4つのターゲットノート |
| 除外 | **フレーズ**（エリーゼのために）ごとであり、記録ごとではないため、同じメロディーのわずかに異なるバージョンが、データに漏れることはありません。 |
| クラス | 一致、ピッチの失敗/警告、タイミングの失敗/合格、見逃し、追加、調和のとれたビブラート、評価する必要のない沈黙 |
| オーディオ | 配布されるレコードはありません。各レコードには、決定的なレシピと、生成される波形のSHA-256が含まれています。 |
| スキーマ | `jam-actions-acoustic-v0/1.0.0` |

9つのクラスのうち2つは、単純なモデルが自信を持って誤った回答をするため存在します。1つは、正しい評価が「調和のとれた」であるビブラートノート、もう1つは、正しい評価が「評価する必要がない」である沈黙です。評価の基礎となるすべての閾値は、記録にコピーされます。これは、両方がビルド中に1回変更されたためです。

このリポジトリからコーパスを再現できます。これを再生成すると、公開されているすべての79個のファイルと、バイト単位で同一の`checksums.sha256`が生成されます。また、テストによって、公開されたツリーを書き込まずに、それが正確であることを確認します。

**測定された、仮定されたものではない、1つの注意点。** 各レコードには、そのレシピが生成する波形のハッシュである`wav_sha256`が含まれており、レンダラーはサンプルごとに`Math.pow`と`Math.sin`を1回呼び出します。どちらも正しく丸められる必要はなく、V8の結果はNode 22とNode 24の間で変化しました。元のコーパスで評価された27,869個の異なる`Math.pow(2, x)`引数のうち、253個は異なるdouble値を返します。そのほとんどは16ビット量子化の下で消えますが、**72件のレコードのうち2件** — Für Eliseの`extra`摂動（そのモチーフは、半音の比率自体が異なるピッチにあります） — は、Node 24で異なるハッシュ値を持ちます。すべてのレコードの他のすべてのフィールドは、どのエンジンでも再現され、リポジトリは両方の主張を個別にテストします。再レンダリングして、これらの2つの不一致が発生した場合、それはこれであり、破損したダウンロードではありません。波形をビットポータブルにするには、超越関数を置き換える必要があります。これにより、すべてのハッシュが変更されるため、新しいスキーマバージョンが必要です。

### Docker

すべてのリリースでは、MCPサーバーをstdioで実行する、軽量なイメージである`ghcr.io/mcp-tool-shop-org/ai-jam-sessions`も公開されます。知っておくべきことは、`/data`がメモリであるということです。ジャーナル、サーバーの状態、ユーザーの曲、および取得されたMIDIはすべてそこに保存されるため、ボリュームをマウントするか、コンテナが終了します。

```json
{
  "mcpServers": {
    "ai_jam_sessions": {
      "command": "docker",
      "args": ["run", "--rm", "-i", "-v", "ai-jam-data:/data", "ghcr.io/mcp-tool-shop-org/ai-jam-sessions"]
    }
  }
}
```

イメージには、再配布可能な14個のMIDIファイルが含まれています。`library fetch --accept-source-terms`をコンテナ内で1回実行すると、残りの94個がボリュームに配置されます。`docker compose up`は、名前付きボリュームを使用して同じことを行い、`--profile ollama`はOllamaサイドカーを追加します。詳細、イメージ内のCLI、および意図的に含まれていないものについては、[docs/docker.md](docs/docker.md)をご覧ください。ファインチューニングされたグレーダーをOllamaで実行し、4ビットベースの測定コストを考慮すると、[docs/ollama-adapters.md](docs/ollama-adapters.md)をご覧ください。

### 歌う

| ツール | そのツールの機能 |
|------|--------------|
| `sing_along` | 歌えるテキスト — 音名、ソルフージュ、旋律、または歌詞。ピアノ伴奏の有無。 |

| `verify_harmony` | メーカーループの検証ゲート：提案されたコードの再構成は、プラットフォーム独自の決定論的ツールによってチェックされる — コードの忠実性（コードエンジンは、意図されたすべてのコードを検出する必要がある）、メロディーの調和（音／緊張感／半音階）、ベースのボイスリーディング、キーの適合性 |
| `auto_reharmonize` | 1回の呼び出しで完了するメーカーループ：ローカルモデルがコードの再構成を提案し、`verify_harmony`の決定論的ゲートがすべてのボイシングをチェックし、検証された解釈が得られるまで、n個の中から最適なものを選択する |
| `compose_panel` | 任意の曲に対して、ボイスリーディングの作曲パネルを実行：4つのシステムが伴奏を作成し、クロスファミリーのLLMがそれらを評価し、ブラッドリー・テリー法で集計 — 解釈不可能な演奏を無効にする識別閾値ゲート（方向性のある信号のみ、品質スコアはなし）。数分間実行し、進行状況をストリーミングで通知する。 |

**曲全体を時計に合わせて：ボーカルのルート。** どんな曲でも、実際に歌われたボーカルをピアノに合わせることができます。
- **時計。** スコア・クロック（`scripts/build-score-clock.mjs`）は、曲の構成に基づいて、各音節の音高、開始タイミング、持続時間を、プレイヤー自身のタイムライン上で決定します。
- **サウンドチェック。** 曲がレンダリングされる前に、同じ声で16語のキャリブレーションフレーズを曲のテンポ（`scripts/soundcheck.py`）で歌います。そのタイミングのパターン（子音グループごと、および短い音符に対して保持される音符ごと）は、曲に必要なテイク数と、どの単語が危険であるかを判断します。GPU時間を曲自体に費やす前に。
- **歌手。** スコアに基づいて調整された歌手（[SoulX-Singer](https://github.com/Soul-AILab/SoulX-Singer)、Apache-2.0）は、そのクロックから16テイクをレンダリングし、ローカルまたはオフリッグを通じてレンタルされたGPU上で実行します。
- **選択。** `scripts/sing_clock.py --by-phrase --warp`は、フレーズごとに1つのテイクを選択します。ローカルのリスナーのトランスクリプトとFCPEの音高が決定し、フレーズはスコアに合わせて時間調整されます。
- **ゲート。** **タイミング：** エネルギー検出器と、歌唱強制アライメントによってクロスチェックされたものが、すべての母音を40ms以内に収めます。**音高：** FCPEが、pYINがフラグを立てたものを再確認し、すべての音符を50セント以内に収めます。
- **耳。** リスニングレビュー（`scripts/review_marks.py`）では、どこかで音が悪いと感じた場合に、カテゴリとメモとともに「M」を押すことができます。レポートは、各マークをそのテイク、結合、およびゲートに追跡し、レビュー担当者のレベルで重み付けします。リスナーの耳は、*どこ*で音が悪いかを判断し、*何*が問題なのかを特定することは、トレーニングによってより重要になります。これは、ローカルのリスニングページとして、およびコックピット内のレビューモードとして実行され、保存されたセッションと、すべてのクリップに対して1つのラウドネスが設定されます。ルート、レバー、およびレシート：[ハンドブック → ボーカル](https://mcp-tool-shop-org.github.io/ai-jam-sessions/handbook/vocals/)、[`docs/vocal-clock.md`](docs/vocal-clock.md）。選択の根拠となる研究：[`docs/vocal-singing-study-2026-09.md`](docs/vocal-singing-study-2026-09.md)。

### 再生

録音されたオーディオを測定します。単音の場合、一度に1つの音符を追跡するため、コードや完全なミックスでは、確実な誤った結果が生じます。すべての数値は、信号処理から得られ、モデルが画像から読み取ることはありません。

| ツール | そのツールの機能 |
|------|--------------|
| `analyze_audio` | WAVファイルを測定します。開始タイミング、音高の輪郭を音名とセントで表示、レベル（BS.1770-4 LUFS、ピークdBFS、クリップされたサンプル）、バンドごとのスペクトルバランス、および整合性チェック（ドロップアウト、ノイズバースト、クリック）。 |
| `transcribe_audio` | 単音の録音を音符に変換し、各音符が基準となる音程からどれだけずれているかを表示します。トラッカーが追跡できなかった音符は、推測するのではなく、省略されます。 |
| `score_audio_take` | ライブラリに登録されている曲と比較して、演奏を**耳で**評価し、その結果を`view_scored_piano_roll`に渡します。 |
| `view_spectrogram` | 音を視覚化します。ピアノのキーボードを軸とした定Qスペクトログラムを、必要に応じて意図された音符と重ねて表示します。デフォルトでは、視覚的な情報が非表示になります。 |
| `check_loop_seam` | ループの終点が開始点にどのように戻るかを判断 — 外挿された波形のステップ、結合におけるバーストエネルギー、それを通じたレベルの変化 |
| `compare_balance` | レンダリングされた画像のトーンバランスを、基準画像と比較します。比較は、dBで、帯ごとに、明るさの変化と傾きを考慮して行います。音量は相殺されます。 |
| `ensemble_now` | 各楽器が**現在**演奏している音を、演奏中に表示します。音符は送信されたものから取得されるため、推定値ではなく正確な値が表示されます。 |

## ステータス

**v2.9.0：実際のピアノ伴奏に合わせた3つの賛美歌。** アメイジング・グレイス、アメリカ・ザ・ビューティフル、バトル・ヒムン・オブ・ザ・リパブリックは、それぞれの賛美歌のために書かれたピアノ伴奏に合わせて歌われ、それぞれが独自のテンポと構成を持ち、フレーズの終わりが休符に繋がります。ボイスゲートがデフォルトで実行されるようになり、バトル・ヒムンでほぼ無音の音節を検出し、再公開される際に修正されました。コックピットにリスニングレビューモードが追加されました。詳細については、[CHANGELOG](CHANGELOG.md)を参照してください。

**v2.8.0：2つの賛美歌を歌う。** アメイジング・グレイスとアメリカ・ザ・ビューティフルは、すべての節を歌い、ピアノのクロックに合わせて演奏されます。16テイク、フレーズごとに1テイク、時間調整の配置、2つの楽器のタイミングと音高のゲート、そして最後に人がリスニングします。どちらも耳で確認され、[ランディングページ](https://mcp-tool-shop-org.github.io/ai-jam-sessions/)で紹介されます。ライブラリの「アメリカ・ザ・ビューティフル」は、現在、ワード自身の「マテルナ」のメロディーです。詳細については、[CHANGELOG](CHANGELOG.md)を参照してください。

**v2.7.0 — アメリカ・ザ・ビューティフル。** ライブラリには、注釈付きの曲が109曲あります。15個のMIDIファイルが同梱され、94個はまだそれぞれのソースから取得されます。新しい曲は、このリポジトリで作成されたパブリックドメインの伴奏（メロディーはサミュエル・A・ワードによる、1882年）で、F長調で、民謡の模範です。SoulX-Singerのルートで歌います。タイミングと音高のゲートが通過し、ランディングページには3つの音高警告が残ります。詳細については、[CHANGELOG](CHANGELOG.md)を参照してください。

**v2.6.0 — 著作権のないものを配布しなくなったリリース**（[CHANGELOG](CHANGELOG.md)を参照）。
曲のライブラリのファイルごとの来歴監査により、108個のMIDI伴奏のうち、14個は再配布を許可するライセンスを持ち、94個は持っていないことがわかりました。また、12個のファイルは、ファイル名とは異なる曲でした。現在、すべての曲には、証拠に基づいた`provenance`ブロック（ソースURL、サイトの利用規約、編曲者がファイルの著作権イベントとして名前を記載、SHA-256、タイトルに関する判断）が含まれています。12個のファイルは隔離され、npmパッケージには14個のファイルが含まれ、残りのファイルは「未取得」とマークされ、`ai-jam-sessions library fetch --accept-source-terms`がそれぞれのサイトから、そのサイトの利用規約に基づいて、ハッシュ値が一致しないファイルは拒否してダウンロードします。以前のバージョンでは、すべての120個のファイルが同梱されており、npmでは非推奨となっています。同じ監査により、検証された伴奏を持つ11曲に、jam-actions-v1データセットがリセットされました（3つのクルーガーCC-BY-SA-3.0-DE、8つのムトピア・パブリックドメイン）。コーパス、ニアゲートプローブ、および表示された作品のターゲットを見つけたトレーニングアークは、3Bランク16のLoRAで、クラスが54/54のホールドアウトと72/72のニアゲートから、レシピが変更されずに1つに収束しました。これらは、リポジトリ内の`datasets/`と`experiments/coverage-v1-sft/`にあり、検証されたコーパスからのHugging FaceとZenodoへの公開は、今後行われます。また、このリリースでは、`scorePerformance`が呼び出し側のゲートで正しいウィンドウを制限するため、40msのハウスルールが正確に検証ウィンドウになります。

以前のv2.5.0のリリースでは、モデルがバンドの演奏を「聞く」ことができるようになりました。

以前のv2.2.0のリリースでは、楽器に実際の「耳」と「リスニングルーム」が備わりました。コックピットのデフォルトのピアノは、現在、**サンプリングされたコンサートグランドピアノ**です。これは、不要な要素が削除されたSalamanderパックであり、最初のジェスチャーでロードされ、準備が整うまでは調整されたオシレーターシンセに切り替わります。サーバーは、完全なパックがインストールされている場合に、自動的にサンプルエンジンを選択します。その上には、**コンポジションパネル**があります。これは、ブラインドで、音量調整されたA/Bリスニングルームであり、人間がコンポジションエンジンのボイシングを、理論的に妥当なアンカーと理論的に妥当でないアンカーに対してランク付けします（ブートストラップCIを使用したブラッドリー・テリー法、MUSHRAスタイルの識別閾値、PROVISIONALおよびUNINTERPRETABLEが、主要な結果として扱われます）。その横には、ローカルモデルパネルがあり、同じランク付けを、クロスファミリーのLLMジャッジを使用して実行します。また、比較ビュー（Kendall τ）があり、安価なプロキシが人間の真実を追跡しているかどうかを尋ねます。

## セキュリティとプライバシー

**アクセスされるデータ：** 楽曲ライブラリ（JSON + MIDI）、ユーザーの楽曲ディレクトリ（`~/.ai-jam-sessions/songs/`）、ギターのチューニング設定、練習日誌のエントリ、ローカルのオーディオ出力デバイス。

**変更されていないデータ（デフォルトのパス）：** MCPサーバーとCLIは、ネットワークへの接続を行わず、認証情報を読み取らず、ユーザーの楽曲ディレクトリ外のシステムファイルにもアクセスしません。テレメトリは収集または送信されません。同じパッケージに含まれる**（オプションの）データセット/評価ツール**（`scripts/run-llm-eval.ts`、プロベナンス検証ツール）は、唯一の例外です。明示的に実行した場合に限り、LLM APIに接続して（環境から`ANTHROPIC_API_KEY`を読み取りますが、保存することはありません）、プロベナンスURLを取得できます。`scripts/arrange-hymn.ts`は、賛歌のピアノアレンジを依頼する際に、実行時にOpenRouterを`OPENROUTER_API_KEY`とともに呼び出し、コストを記録します。サーバー、CLI、またはインストールの一部として実行されることはありません。

**権限：** MCPサーバーは、stdioトランスポートのみを使用します（HTTPは使用しません）。CLIは、ローカルファイルシステムとオーディオデバイスにアクセスします。完全なポリシーについては、[SECURITY.md](SECURITY.md)を参照してください。
