## まず聞いてください：3つの賛歌を、リズムに合わせて歌います

**[Amazing Grace、America the Beautiful、そしてBattle Hymn of the Republic](https://mcp-tool-shop-org.github.io/ai-jam-sessions/#listen)**。
各節を、それぞれの賛歌のために書かれたピアノ伴奏に合わせて、合成音声で歌います。ランディングページでは、3Dの楽譜とともに再生され、音声と歌詞に合わせて楽譜が点灯します。

各演奏は、楽譜に基づいて調整されたボーカルの16テイクから構成されています。
- 各フレーズにつき1テイクで、ローカルのリスナーとピッチトラッカーによって選択されます。
- 時間調整を行い、楽譜上に配置することで、フレーズ内の部分が途切れることがありません。
- 2つのタイミング測定器と2つのピッチトラッカーによってチェックされます。
- 最終的に、聴覚による確認が行われ、問題があれば、その原因まで遡ってレビューに記録されます。

各曲の前に、音声チェックを行い、音声のタイミングの特性を測定し、その曲に必要なテイク数を決定します。

制作方法：[ハンドブック → ボーカル](https://mcp-tool-shop-org.github.io/ai-jam-sessions/handbook/vocals/)。

| | Amazing Grace | America the Beautiful | Battle Hymn |
|---|---|---|---|
| 楽譜から40ミリ秒以内の音節 | 112件中107件 | 224件中217件 | 414件中283件 |
| 50セント以内の音 | 140件中135件 | 224個中218個 | 424件中360件 |

Battle Hymnの速い付点音符は、歌手自身のタイミングで演奏されるため、タイミングのずれが生じやすい。

音声は合成音声です：[SoulX-Singer](https://github.com/Soul-AILab/SoulX-Singer)（Apache-2.0）。独自の音色を持ち、実際の歌手を模倣していません。ピアノ伴奏は、このプロジェクトのためにKimi-K3が作曲し、パブリックドメイン（CC0）に提供されています。3つの賛歌はすべてパブリックドメインです。

## これは何ですか？

AIが演奏を学習するピアノとギターです。シンセサイザーでも、MIDIライブラリでもありません。これは、AIに音楽を教えるための楽器です。

LLMはテキストを読み書きできますが、私たちが音楽を体験するのと同じようには体験できません。耳もなければ、指もなければ、筋肉の記憶もありません。AI Jam Sessionsは、モデルが実際に使用できる感覚を与えることで、このギャップを埋めます。

- **読解** — 音楽的な注釈が深く加えられた、実際のMIDI楽譜。手書きの近似ではなく、解析、分析、説明が行われます。
- **聴覚** — 6つのオーディオエンジン（オシレーターピアノ、サンプルピアノ、ボーカルサンプル、物理的なボーカルトラクト、加算型ボーカルシンセ、物理的にモデル化されたギター）が、スピーカーを通して再生され、部屋にいる人々がAIの耳になります。そして今、モデルは独自の耳を持つことになります。録音を後で測定できるだけでなく（[聴覚](#listening)を参照）、音楽が演奏されている間にもバンドを**観察**できます（[ライブアンサンブル](#the-live-ensemble)を参照）。
- **視覚** — ピアノロールは、演奏された内容をSVGとしてレンダリングし、モデルが読み込んで検証できるようにします。インタラクティブなギタータブ譜エディター。視覚的なキーボード、デュアルモードのノートエディター、チューニングラボを備えたブラウザのコックピット。
- **記憶** — セッション間で持続する練習ジャーナルにより、学習が時間とともに蓄積されます。
- **歌唱** — 20種類の音声プリセットを備えたボーカルトラクト合成。ソフィー、輪郭、音節によるナレーションを備えた、一緒に歌えるモード。そして、ピアノのクロックに合わせて歌われる楽曲全体：楽曲の構成に基づいて調整された楽譜、多くのテイクからフレーズごとに組み立てられ、タイミング（40ミリ秒）とピッチ（50セント）でゲート処理された後、聴くことができる楽曲です（[歌唱](#sing)を参照）。

現在、109曲すべてに完全な注釈が加えられています。歴史的背景、小節ごとの構造分析、重要なポイント、教育目標、パフォーマンスのヒントなど、すべての12のジャンルについて。このREADMEの以前のバージョンでは、生の楽曲は「AIがパターンを吸収し、音楽を演奏し、独自の注釈を作成するのを待っている」と記載されていました。まさにそれが起こりました。注釈は、決定論的な楽曲ごとの分析（コード、反復構造、セクションの境界、コンテンツが検証されたキー）に基づいてAIによって作成され、品質基準によってゲート処理され、そして、主張ごとに反対意見による事実確認が行われました。測定番号、コードウィンドウ、構造カウントはすべて、実際のMIDIに対して検証された後に出力されました。

この作業から、**[jam-actions-v0](#training-dataset)**も公開します。これは、実際のクラシックピアノ音楽を使用した、57回の多段階のMCPツール使用のパブリックデータセットです。LLMに、テキスト生成だけでなく、シンボリック音楽における*具体的なツール使用*を学習させます。また、7軸のリリースゲートを備えており、「証拠を提示する」ことと「タスクが些細なため合格とする」ことを区別します。詳細については、[トレーニングデータセット](#training-dataset)を参照してください。

## 試聴

以前は、このサーバーは音を出すことはできましたが、分析することはできませんでした。モデルが演奏し、人がそれを聞き、モデルはその人の意見を尊重していました。しかし、そのギャップは今や解消されました。

WAVファイルを指定すると、その内容を測定します。楽譜に対して現在使用しているのと同じ種類のツールを使用して信号を処理することで、画像を見て推測するのではなく、測定を行います。

- **`analyze_audio`** — 音の始まり、ピッチの輪郭、レベル。ピッチは、セント単位のずれとともに、音名として表現されます。生の周波数としては表現されません。レベルは、現在の実際の数値を示します。BS.1770-4に準拠したLUFS単位の統合ラウドネス、dBFS単位のサンプルピーク、クリップされたサンプルの数、そしてドロップアウトやノイズの発生を報告する整合性チェックが含まれます。これらは、レンダリングの品質管理におけるクリック音やグリッチの半分の部分です。バランスセクションでは、サブベースから高音域まで、エネルギーがどのように分布しているかを示します。各バンドがピンクノイズに対してどの程度の割合を占め、明るさや傾きがどのようになっているかを表示します。
- **`transcribe_audio`** — 録音を音符として表現：ピッチ、開始時間、持続時間、そして各音符がコンサートピッチからどれだけ離れているか。
- **`score_audio_take`** — ライブラリ内の曲に対して、耳で判断しながら演奏の質を評価します。録音をトランスクライブし、楽譜と照合し、どの音符が正しく演奏されたか、どの音符がずれたか、そしてどの音符が演奏されなかったかを報告します。その後、`view_scored_piano_roll`がその結果を楽譜上に表示します。これは、キャプチャされたMIDIデータに対して行うのと同じように行われます。これにより、実際の楽器、歌声、またはMIDIデータがないものを評価することができます。
- **`view_spectrogram`** — 音を視覚化します。一定のQ値を持つスペクトログラムで、左端にピアノの鍵盤を表示し、ピッチが一目でわかるようにします。また、必要に応じて、曲の意図された音符をその上に表示します。
- **`check_loop_seam`** — ループ再生の終端がどのように繋がるかを評価します。波形のステップ、終端の傾きを外挿した後のエネルギーの分布、接続部でのレベルの変化を評価します。位相が完全に一致したループは、生の境界サンプルがジャンプしても、スムーズに聞こえます。
- **`compare_balance`** — 参照となる、正しいことがわかっているレンダリングに対して、バンドごとにdB単位で音色を比較します。他の音と同様に聞こえるべき音、置き換えるべき録音に一致するべき再レンダリング。ラウドネスは相殺されるため、音色のみが比較されます。

**ただし、以下のことはわかりません。**画像は、問題のある箇所を特定するために使用されます。すべての数値は、信号処理から得られ、モデルが画像を読み取って得られるものではありません。トランスクライバーは一度に1行を処理するため、コードや完全なミックスは、確実ですが誤った結果を生み出し、その旨を伝えます。最新技術では、発音の検出精度は約F1 0.88であり、したがって「見逃された」音符は、実際に演奏されなかった音符ではなく、トランスクライバーが聞き取れなかった音符である可能性があります。これらのツールは、その点に注意を払い、結果にその点を明記します。

全体的な構造は、依存関係がありません。変換、ピッチトラッカー、発音検出器、WAVデコーダー、PNGエンコーダーはすべてこのリポジトリにあり、Nodeとブラウザの両方で同じ数値を生成します。

## ライブ・アンサンブル

試聴機能は、録音を完了した後に評価します。これは、その逆の機能です。演奏中に、各楽器が**現在**何をしているかを尋ねます。

```
ensemble_now()
```

各楽器の持続音、その持続時間、およびアンサンブル全体のコードを返します。デュエットの場合、2つの音声は個別に報告されるため、ピアノが三和音を保持し、シンセがその上にメロディーを演奏している様子を確認できます。

### 2つのチャンネルがあり、安価な方が正確です

これは理解しておくべき部分であり、どの数値を信頼するかを決定します。

**意図 - 各エンジンに演奏するように指示されたこと。**モデルが演奏する場合、これは推定ではありません。ピアノのコードは、トランスクライブするものではなく、送信された3つのノートオンです。ノートは正確で、自由で、即時です。

**音響 - 実際にどのような音が鳴ったか。**各エンジンは、出力をプライベートな分析バスに送ることができるため、すべての楽器は、分離や曖昧さなしに、ソースで測定されます。このチャンネルは、**発見ではなく検証**です。これにより、音声がタイミングからずれたり、録音が途切れたり、エンジンがノートを送信され続けているにもかかわらず沈黙したりしたことを知ることができます。

2つの結果が一致しない場合、それはレンダリングに関する事実であり、ノートの修正ではありません。

### コスト

楽器を監視するには、42.67msのブロックに対して、約**9マイクロ秒/オーディオコールバック**かかり、これはオーディオバジェットの約0.02%であり、サンプルが1つもドロップしていない状態で測定されます。オブザーバーがアタッチされていない楽器は、まったくコストがかかりません。

### ただし、以下のことはわかりません

音響チャンネルは遅れており、その遅延量を示します。約23ms（ピッチ）、および70ms（確認された発音）です。これは、その後のオーディオが到着するまで、発音を確認できないためです。そのエッジに近い発音は、報告されてから後で取り下げられるのではなく、保留されます。

音響トラッカーは一度に1行を追跡するため、コードのノートを特定することはできません。また、そうしようともしません。解決できないコードは、既知の制限であり、アンサンブルは、ピアノが演奏するすべてのコードで「狼少年」のように叫ぶのではなく、静かにします。

## ピアノロール

ピアノロールは、AIが音楽をどのように認識するかを示します。AIは、あらゆる曲をSVG形式でレンダリングします。右手の音は青色、左手の音はコーラル色で表示され、ビートグリッド、ダイナミクス、小節の境界線も表示されます。

## コックピット

このリポジトリの[`apps/cockpit`](apps/cockpit)にある、ブラウザベースの作曲スタジオです。また、**[mcp-tool-shop-org.github.io/ai-jam-sessions/cockpit](https://mcp-tool-shop-org.github.io/ai-jam-sessions/cockpit/)**でライブで実行できます。プラグイン、DAW、インストールは不要です。すべてがブラウザ内で動作し、作業内容は自動的にローカルに保存されます。ハッキングしたい場合は？

```bash
cd apps/cockpit && npm install && npm run dev   # Vite dev server, opens in your browser
```

- **デフォルトでは、サンプリングされたコンサートグランドピアノ** — コックピットには、トリミングされたSalamander Grandパック（90個のOGGファイル、8MB）が同梱されており、最初に操作するとロードされ、シンセサイザーの音と同じ出力チェーンを通じて再生されます。ロードされる前（またはオフラインの場合）は、調整されたオシレーターピアノがシームレスにカバーします。サンプルは[Alexander Holm](https://freepats.zenvoid.org/Piano/acoustic-grand-piano.html)によるもので、CC-BY 3.0ライセンスです。
- **パネルモード — リスニングルーム** — 作曲エンジンの音色を、実際のライブラリのメロディーに対して、ブラインドのペアワイズA/Bオーディションを行います。ラウドネスが調整されたクリップを、実際の音声パスを通じてオフラインでレンダリングし、隠された最小限の試行を含む、シードされたシャッフルされた試行を行い、Bradley-Terryランキングとブートストラップ信頼区間を使用して、正直な結果を得ます（すべてのペアが投票の予算に達するまで一時的な結果、識別しきれない場合は解釈できません）。2番目のサブモードでは、ローカルのLLMジャッジを使用して同じランキングを実行し、さらに両方の種類の実行結果の履歴と、比較ビュー（Kendall τ + エンジンランクの一致）を表示します。これにより、安価なプロキシが人間の真実を追跡しているかどうかを確認します。
- **正確なビートに同期したトランスポート** — 音符は音楽的な時間で表現されるため、BPMコントロールは実際に再生時間を調整します。クリックしてシークできるタイムルーラーと、ドラッグして**ループ領域**を設定できます。自動スクロール機能により、再生ヘッドを追跡できます。
- **録音開始時のキャプチャ** — QWERTYキー、オン スクリーンキーボード、またはWeb MIDIデバイスを演奏すると、楽譜に記録されます。1小節のカウントイン、ループサイクル全体にわたるルーパースタイルのオーバーダブ（または置換モード）、生のパフォーマンスタイミングを保存し、量子化されたビューで表示します。各パスは、元に戻せる1つの単位として保存されます。
- **完全な元に戻し/やり直し** — ClearやImportを含むすべての編集は元に戻すことができます（Ctrl+Z）。ドラッグジェスチャーは、実際の編集ツールと同様に統合されます。
- **複数選択 + クリップボード** — Select/Drawツールを切り替えて、領域を選択します。プラットフォーム標準の修飾キーをクリックし、コピー/カット/ペーストを再生ヘッドで行い、複製します。
- **タッチ + アクセシビリティ** — すべてのサーフェスでキャプチャされたポインターイベント、ドラッグの代替手段としてタップして再配置、キーボードによる音符の編集、色覚異常の人でも識別しやすい楽譜のオーバーレイ。
- **デュアルモードのピアノロール** — インストルメントモード（クロマティックピッチクラスの色）とボーカルモード（音符が母音の形状で色分け：/a/ /e/ /i/ /o/ /u/）を切り替えます。
- **視覚的なキーボード** — C4から2オクターブ、QWERTYキーボードにマッピングされています。クリックまたは入力します。
- **20種類のボイスプリセット** — 15種類のKokoroマッピングされたボイス（Aoede、Heart、Jessica、Sky、Eric、Fenrir、Liam、Onyx、Alice、Emma、Isabella、George、Lewis、および合唱とシンセボイス）、4種類のトラクトマッピングされたボイス、および合成合唱セクション。
- **10種類の楽器プリセット** — サーバー側の6つのピアノボイスと、シンセパッド、オルガン、ベル、ストリングス。
- **音符インスペクター** — 任意の音符をクリックして、ベロシティ、母音、および息の強さを編集します。
- **7種類のチューニングシステム** — 平均律、純正律（長調/短調）、ピタゴラス音階、四分音差平均律、ヴェルクマイスターIII、またはカスタムセントオフセット。調整可能なA4基準（392〜494 Hz）。
- **チューニング監査** — 周波数テーブル、ビート周波数分析によるインターバルトエスター、およびチューニングのエクスポート/インポート。
- **楽譜のインポート/エクスポート** — 楽譜全体をJSONとしてシリアライズし、ロードします。
- **LLM対応API** — `window.__cockpit`は、`exportScore()`、`importScore()`、`addNote()`、`play()`、`stop()`、`panic()`、`setMode()`、および`getScore()`を公開し、LLMがプログラムで作曲、編曲、および再生できるようにします。

## 曲のライブラリ

12のジャンルにわたる109曲のアノテーション付き楽曲。これらは実際のMIDIファイルから作成されています。各ジャンルには、詳細なアノテーションが施された代表的な楽曲が1つずつ含まれており、歴史的背景、小節ごとの和声分析、重要なポイント、教育目標、演奏のヒント（ボーカル指導を含む）が記載されています。これらの代表的な楽曲はテンプレートとして機能します。AIはまず1つの楽曲を学習し、その後残りの楽曲にアノテーションを付与します。フォークの代表的な楽曲は、「アメリカの美しい」（サミュエル・A・ワード、1882年、パブリックドメイン）です。これはF長調の賛美歌で、このリポジトリに収録されており、メロディーはF4〜C5です。

**What ships, and what you fetch.** The annotations are ours and ship with every song. The MIDI files were downloaded from public MIDI sites when the library was built, and a per-file provenance audit ([`docs/findings/library-provenance-audit.md`](docs/findings/library-provenance-audit.md)) found that only 14 of those downloads carry a licence that permits redistribution — Bernd Krueger's piano-midi.de arrangements (CC-BY-SA-3.0-DE) and the Mutopia Project's public-domain typesettings. Those 14 are in the npm package. The other 94 downloads are not: their `.json` ships, with a `provenance` block naming the source, its terms and the file's SHA-256, and `ai-jam-sessions library fetch --accept-source-terms` downloads each one from the site that published it, under that site's terms, refusing any file whose hash no longer matches what the annotations were verified against. Twelve files that turned out to be a different piece than their name were quarantined, which is why that downloaded library is 108 songs and not the 120 earlier versions claimed. **America the Beautiful** is the 109th song and the fifteenth MIDI the package ships: the arrangement was made here and dedicated to the public domain. Versions before 2.6.0 shipped all 120 MIDI files; that was a mistake, and it is corrected here rather than papered over.

## 練習日誌

各セッションの後、サーバーは、どの曲、どの速度、何小節、どれくらいの時間演奏したかを記録します。AIは、何に気づいたか、どのようなパターンを認識したか、次に何を試すべきかを自身の考察として追加します。

```markdown
---
### 14:32 — Autumn Leaves
**jazz** | intermediate | G minor | 69 BPM × 0.7 | 32/32 measures | 45s

The ii-V-I in bars 5-8 (Cm7-F7-BbMaj7) is the same gravity as the V-i
in The Thrill Is Gone, just in major. Blues and jazz share more than the
genre labels suggest.

Next: try at full speed. Compare the Ipanema bridge modulation with this.
---
```

1日に1つのマークダウンファイルとして、`~/.ai-jam-sessions/journal/`に保存されます。人間が読める形式で、追記のみが可能です。次のセッションでは、AIはその日誌を読み、中断したところから再開します。

### 音響コーパス

**jam-actions-acoustic-v0** — 上記のトレースに対応するもので、シンセサイザー音楽ではなく、**オーディオ**を対象としています。72レコードで、それぞれ、意図的に変更されたパブリックドメインのフレーズの合成レンダリングと、分析ツールが実際に返す結果をペアにしています。これにより、すべてのラベルが、それ自体に対してだけでなく、楽器に対しても検証されます。

| | |
|---|---|
| バージョン | 1.1.0（2026年9月25日）— 1.0.xの36件の「Träumerei」レコードを削除しました。これらのレコードのソースファイルには、確立された編曲ライセンスがありません。 |
| レコード | 72 — 2つのフレーズ（バッハ、エリーゼのために）× 9種類の摂動 × 4つのターゲットノート |
| 除外 | **フレーズ**（エリーゼのために）ごとであり、記録ごとではないため、同じメロディーのわずかに異なるバージョンが、データに漏れることはありません。 |
| クラス | 一致、ピッチの失敗/警告、タイミングの失敗/合格、見逃し、追加、調和のとれたビブラート、評価する必要のない沈黙 |
| オーディオ | 配布されるものはありません。各記録には、決定的なレシピと、生成される波形のSHA-256が含まれています。 |
| スキーマ | `jam-actions-acoustic-v0/1.0.0` |

9つのクラスのうち2つは、単純なモデルが自信を持って誤った回答をするため存在します。1つは、正しい評価が「調和のとれた」であるビブラートノート、もう1つは、正しい評価が「評価する必要がない」である沈黙です。評価の基礎となるすべての閾値は、記録にコピーされます。これは、両方がビルド中に1回変更されたためです。

このリポジトリからコーパスを再現できます。これを再生成すると、公開されているすべての79個のファイルと、バイト単位で同一の`checksums.sha256`が生成されます。また、テストによって、公開されたツリーを書き込まずに、それが正確であることを確認します。

**ただし、1つの注意点があります。これは仮定ではなく、測定されたものです。** 各レコードには、そのレシピが生成する波形のハッシュである`wav_sha256`が含まれており、レンダラーはサンプルごとに`Math.pow`と`Math.sin`を1回呼び出します。これらは正しく丸められる必要はなく、V8の結果はNode 22とNode 24の間で変化しました。元のコーパスで評価された27,869個の異なる`Math.pow(2, x)`引数のうち、253個は異なるdouble値を返します。そのほとんどは16ビット量子化によって解消されますが、**72個のレコードのうち2個**—どちらもエリーゼのための第1番の`extra`摂動で、そのモチーフは、半音の比率自体が異なる単一のピッチにあります—は、Node 24で異なるハッシュ値を持ちます。すべてのレコードの他のすべてのフィールドは、どのエンジンでも再現され、リポジトリは両方の主張を個別にテストします。再レンダリングして、これらの2つの不一致が発生した場合、それはこの問題であり、ダウンロードが破損しているわけではありません。波形をビットポータブルにするには、超越関数を置き換える必要があります。これにより、すべてのハッシュが変更されるため、新しいスキーマバージョンが必要になります。

### 独自のものを構築する

コーパスが実行されるための足場は、独自の実験に使用できます。
[`experiments/_template/`](experiments/_template/)は、コピーできる動作する例です。タスクを宣言すると、SFT形式、クラスごとのスコアリング、宣言された評価セットに対する単純なベースライン、および分割をまたがないように、ホールドアウトユニットがないかのチェックが提供されます。

[契約](experiments/_template/README.md) の内容は読む価値があります。正解データは、手作業で作成するのではなく、構築可能であり、ラベルはツールが測定した値と照合して検証されます。また、データの漏洩を防ぐために、適切な単位で分割し、ベースラインとベースモデルを結果とともに報告します。これらのルールを学習するには、それぞれコストがかかります。

**曲全体を時間軸に沿って：ボーカルルート。** 任意の曲に、実際に歌われたボーカルをピアノに合わせることができる。
- **時間軸。** 採点時間軸（`scripts/build-score-clock.mjs`）は、曲の構成から各音節の音高、開始時間、および持続時間を導き出し、演奏者の独自のタイムラインに適用する。
- **サウンドチェック。** 曲がレンダリングされる前に、同じ声で曲のテンポ（`scripts/soundcheck.py`）で16語のキャリブレーションフレーズを歌う。そのタイミングのフットプリント（子音グループごと、および短い音符に対して持続音）、曲に必要なテイク数、およびGPU時間を費やす前にリスクのある単語を判断する。
- **歌手。** 採点に条件付けされた歌手（[SoulX-Singer](https://github.com/Soul-AILab/SoulX-Singer)、Apache-2.0）は、その時間軸から16テイクをレンダリングし、ローカルまたはレンタルGPUでoffrigを使用して実行する。
- **選択。** `scripts/sing_clock.py --by-phrase --warp`は、フレーズごとに1つのテイクを選択する。ローカルリスナーのトランスクリプトとFCPEの音高が決定し、フレーズは時間軸に沿って採点に適用される。
- **ゲート。** **タイミング：** エネルギー検出器と、歌唱強制アライメントによってクロスチェックされ、すべての母音を40ミリ秒以内に収める。**音高：** FCPEと、pYINがフラグを立てたものを再読み込みし、すべての音符を50セント以内に収める。
- **耳。** リスニングレビュー（`scripts/review_marks.py`）では、何かがおかしいと感じたときに、カテゴリとメモとともに「M」キーを押すことができる。レポートは、各マークをそのテイク、結合、およびゲートにトレースし、レビューアーのレベルで重み付けする。リスナーの耳は、どこがおかしいかを判断し、トレーニングされたレビューアーは、それが何であるかをより正確に判断する。現在、これはローカルのリスニングページであり、次にコックピットに移行する。ルート、レバー、およびレシート：[ハンドブック → ボーカル](https://mcp-tool-shop-org.github.io/ai-jam-sessions/handbook/vocals/)、[`docs/vocal-clock.md`](docs/vocal-clock.md)。選択の根拠となる研究：[`docs/vocal-singing-study-2026-09.md`](docs/vocal-singing-study-2026-09.md)。

### 再生

録音されたオーディオを測定します。単音の場合、一度に1つの音符を追跡するため、コードや完全なミックスでは、確実な誤った結果が生じます。すべての数値は、信号処理から得られ、モデルが画像から読み取ることはありません。

| ツール | そのツールの機能 |
|------|--------------|
| `analyze_audio` | WAVファイルを測定 — 開始時間、音符名とセントで表される音高の輪郭、レベル（BS.1770-4 LUFS、ピークdBFS、クリップされたサンプル）、バンドごとのスペクトルバランス、および整合性チェック（ドロップアウト、ノイズバースト、クリック） |
| `transcribe_audio` | 単音の録音を音符に変換し、各音符が基準となる音程からどれだけずれているかを表示します。トラッカーが追跡できなかった音符は、推測するのではなく、省略されます。 |
| `score_audio_take` | ライブラリに登録されている曲と比較して、演奏を**耳で**評価し、その結果を`view_scored_piano_roll`に渡します。 |
| `view_spectrogram` | 音を視覚化します。ピアノのキーボードを軸とした定Qスペクトログラムを、必要に応じて意図された音符と重ねて表示します。デフォルトでは、視覚的な情報が非表示になります。 |
| `check_loop_seam` | ループの終点が開始点にどのように戻るかを判断 — 外挿された波形のステップ、結合におけるバーストエネルギー、それを通じたレベルの変化 |
| `compare_balance` | レンダリングの音色のバランスを、バンドごとにdB単位で参照と比較し、明るさと傾きの変化を評価。音量は打ち消される |
| `ensemble_now` | 各楽器が**現在**演奏している音を、演奏中に表示します。音符は送信されたものから取得されるため、推定値ではなく正確な値が表示されます。 |

## ステータス

**v2.8.0：2つの賛歌を演奏。** 「Amazing Grace」と「America the Beautiful」を、ピアノの時計に合わせて、全歌詞、すべての節を演奏。16テイク、各フレーズにつき1テイク、ワープ配置、2つの楽器のタイミングとピッチゲート、そして最後に人がそれを聴く。どちらも耳で確認し、[ランディングページ](https://mcp-tool-shop-org.github.io/ai-jam-sessions/)で紹介されている。ライブラリの「America the Beautiful」は、現在Ward自身の「Materna」のメロディーになっている。詳細については、[CHANGELOG](CHANGELOG.md)を参照。

**v2.7.0 — 「America the Beautiful」。** ライブラリには109曲の注釈付きの曲が含まれている。15個のMIDIファイルが同梱され、残りの94個はそれぞれのソースから取得される。新しい曲は、このリポジトリで作成されたパブリックドメインの編曲で、（作曲：Samuel A. Ward、1882年）、F長調で、民謡の模範となっている。SoulX-Singerがそれを演奏する：タイミングとピッチゲートが通過し、ランディングページには3つのピッチ警告が表示される。詳細については、[CHANGELOG](CHANGELOG.md)を参照。

**v2.6.0 — the release that stops shipping what it had no licence to ship** (see [CHANGELOG](CHANGELOG.md)).
A per-file provenance audit of the song library found that of the 108 MIDI arrangements, 14 carry a
licence that permits redistribution and 94 do not — and that twelve files were a different piece
than their name. Every song now carries an evidence-backed `provenance` block (source URL, the
site's terms, the arranger as the file's own copyright event names them, SHA-256, title verdict);
the twelve are quarantined; the npm package ships the 14 and marks the rest *unfetched*, and
`ai-jam-sessions library fetch --accept-source-terms` downloads each from the site that published
it, under that site's terms, refusing any file whose hash no longer matches. Earlier versions shipped
all 120 files and are deprecated on npm. The same audit reset the jam-actions-v1 dataset to the
eleven songs whose arrangements are verified (three Krueger CC-BY-SA-3.0-DE, eight Mutopia Public
Domain); the corpus, its near-gate probe and the training arc that found the shown-work target — a
3B rank-16 LoRA at one unchanged recipe going from a class prior to 54/54 held-out and 72/72 near
the gate once the assistant turn wrote the digits of the comparison — are in the repo under
`datasets/` and `experiments/coverage-v1-sft/`, with publication to Hugging Face and Zenodo to
follow from the verified corpus. Also in this release: `scorePerformance` caps the correct window
at the caller's gate, so the 40 ms house rule is exactly the verdict window.

以前のv2.5.0では、モデルがバンドの演奏を「見る」ことができるようになった。
`ensemble_now`は、音楽が流れている間に、各楽器が何をしているかを報告する：各楽器の持続音、その持続時間、および組み合わせたコード。2つのチャンネルで実行され、安価なものが正確である。このサーバーが実行すると、送信したものを正確に把握するため、コードは3つのノートオンとして表現され、トランスクリプションの問題ではない。一方、別の音響タップが各エンジンを**ソースで**測定して検証する。測定されたコストは約**1オーディオコールバックあたり9マイクロ秒**であり、レイテンシーは明示的に示されている（〜23msのピッチ、〜70msの確実な発音）。制限は文書化されており、実行可能である。トラッカーはモノフォニックであり、レイヤー化された子要素は個別にタップされ、ミックスとしてタップされることはない。また、タップがない楽器は無音の楽器ではない。
同じリリースでは、データセットの仕組みを、誰でも宣言できる契約に変換し、作業済みのテンプレートを提供することで、ユーザーは独自のコーパスを構築し、同じ基準で独自のアダプターをトレーニングできるようにした。その過程で、音響コーパスの再現性のゲートが、115件の公開されたパスのうち109件をカバーすることが判明し、6件のうち3件は、そもそもジェネレーターによって出力されなかったことが判明した。削除されたものを再生成すると、すべてのファイルとチェックサムマニフェストがバイト単位で完全に再現される。ライブ環境には、**54個のツールと4つのプロンプトテンプレート**があり、**165個のファイルで3,389個のテストが合格し（1個スキップ）**。

以前のv2.4.0のリリースでは、モデルに「耳」が与えられました。4つのツールが、オーディオのレンダリングと分析の間のギャップを埋めました。`analyze_audio`は、音の開始、音程の輪郭、レベルを分析します。`transcribe_audio`は、単音の録音を音符に変換します。`score_audio_take`は、演奏を耳で評価し、その結果を既存のスコアリングされたピアノロールにそのまま渡します。そして、`view_spectrogram`は、定Q、ピアノのキーボードを軸とした音を視覚化します。これらすべては、依存関係のない信号処理であり、このリポジトリに記述された独自のFFT、ウィンドウ、メル、定Q変換、音の開始検出、音程追跡で構成されています。モデルは画像を信頼性を持って目で確認できないため、決定的なクエリが、正確な答えを持つ質問に対して推論よりも優れています。このリリースでは、**jam-actions-acoustic-v0**、つまり、オーディオに対するツールの使用に関する108件の構築可能な正解データも公開されました。

以前のv2.3.0では、楽器が時計に合わせて歌うことを学習した（[CHANGELOG](CHANGELOG.md)を参照）。ライブラリの任意の曲は、ピアノで演奏される実際の歌のラインを含めることができる。**スコアクロック**は、曲のMIDIから、各音節のピッチ、発音、および持続時間を、プレイヤー自身のタイムラインで導き出す。ローカルのApache-2.0ライセンスの、スコアに依存するシンガー（[SoulX-Singer](https://github.com/Soul-AILab/SoulX-Singer)）がそれを歌い、2つのゲートが、何かがミックスとして呼ばれる前に、そのアーティファクトを測定する。タイミング（すべての母音がスコアから40ms以内）、およびピッチ（すべての音が50セント以内）。同梱されている「Amazing Grace」の実行では、最悪のタイミングは6ms、グローバルピッチは-2.7セントであり、その結果はコミットされている。ランディングページには、正直な状態として表示され、残りの1つの欠陥（オープニングのスプライス）も明記されている。そのルート、そのレバー、および各選択の背後にある研究（5つの研究分野、引用）は、[ハンドブック](https://mcp-tool-shop-org.github.io/ai-jam-sessions/handbook/vocals/)と[`docs/`](docs/)に記載されている。ライブ環境は変更されておらず、**49個のツールと4つのプロンプトテンプレート**があり、**3,080個のテストが合格し（1個スキップ）**、さらにボーカル楽器自身のpytestスイートがある。**公開状態：**公開済み — [`@mcptoolshop/ai-jam-sessions@2.3.0`](https://www.npmjs.com/package/@mcptoolshop/ai-jam-sessions)（npm）。

以前のv2.2.0では、楽器に実際の耳とリスニングルームが与えられた。コックピットのデフォルトのピアノは、現在**サンプリングされたコンサートグランド**である。これは、最初のジェスチャーでロードされ、準備が整うまで調整されたオシレーターシンセにフォールバックする、プルーニングされたサラマンダーパックである。サーバーは、完全なパックがインストールされている場合に、自動的にサンプルエンジンを選択する。その上には、**作曲パネル**がある。これは、ブラインドで、音量調整されたA/Bリスニングルームであり、人間が作曲エンジンのボイシングを、理論的に妥当なアンカーと理論的に妥当でないアンカーに対してランク付けする（ブートストラップCIを使用したブラッドリー・テリー、MUSHRAスタイルの識別フロア、PROVISIONALおよびUNINTERPRETABLEを一次的な結果として扱う）。その横には、ローカルモデルパネルがあり、同じランキングをクロスファミリーのLLMジャッジで実行し、比較ビュー（Kendall τ）があり、安価なプロキシが人間の真実を追跡しているかどうかを尋ねる。

同じリリースには、パネルにデータを供給する作曲エンジン（`src/compose/`：名前付きのスタイルプリセットを持つ決定的なボイスリーディングゲート、構成要素によるボイシング仕様、一度に1つのパートを処理するリファイナー）が含まれています。また、完全な健全性チェック（45件の問題を修正：セキュリティの強化、人間らしいストリング、視覚的な整合性を維持する修正）、Mutopiaのパブリックドメインのデータから再構築されたサティとドビュッシーのライブラリのエントリ、および、より堅牢なテスト（記述的な検証エラー、構造化された`{code, message, hint}`エラーエンベロープ、キュレーションされたtarボール、長時間のツールの進行状況通知、CLIエラーの文法）が含まれています。このリリースは、49個のツール、4つのプロンプトテンプレート、および3,033個のテストとともに、[`@mcptoolshop/ai-jam-sessions@2.2.0`](https://www.npmjs.com/package/@mcptoolshop/ai-jam-sessions)としてリリースされました。

以前のv2.1.0では、アナリストが**クリエイター**になった。クリエイターループは、製品として出荷される。モデルがライブラリの任意の曲の再ハーモナイゼーションを提案し、プラットフォーム自身の決定論的なツールがそれをゲートする。コードエンジンは、すべての意図されたボイシングを確認する必要がある（`verify_harmony`）、すべてのメロディーノートは新しいハーモニーに対してラベル付けされ、検証された解釈のみが`add_song` → `play_song` → `view_piano_roll`に進む。生成は、構築によって検証される。ルーブリックはなく、自己評価もない。ジャムブリーフを作成するのと同じ`inferChord`が、ジャッジとなる。`maker_loop`プロンプトテンプレートは、このループ全体を網羅する。

以前のバージョン2.0.0では、データセットがその有用性を証明しました。**重要な変更点：Node.jsの最小バージョンが22に更新されました**（`node-web-audio-api` 2.0）。ツールの基本機能は変更されていません。引き続き、6つのサウンドエンジン、47のMCPツール、3つのプロンプトテンプレート、および**完全に注釈が付けられたライブラリ（12のジャンルにわたる120曲/120曲）**が含まれます（このリリースでは、12の主要フィールドがコンテンツに基づいて検出されたキーに修正されました）。学習ループはエンドツーエンドで閉じられています。メトロノーム（カウントイン付き）→ライブ録音→ノートごとの採点→採点されたピアノロール→クリーンな演奏後にテンポが徐々に上がる練習ループ。ブラウザのインターフェースは、実際の作曲ツールです。ループ領域、録音開始、完全な取り消し/やり直し、複数選択とクリップボード、タッチサポートを備えた、正確なタイミングでの再生が可能です。[ウェブ上で利用可能](https://mcp-tool-shop-org.github.io/ai-jam-sessions/cockpit/)。

また、**[jam-actions-v0](#training-dataset)**も公開しました。これは、クラシックピアノにおける複数ターンのMCPツールの使用履歴を記録した57件のトレーニングデータセットです。7軸のリリースゲート、コールドスタート時の再現性、および完全なZenodo + CITATION.cffメタデータ（CC-BY-SA-3.0-DE）を備えています。これは[Hugging Face](https://huggingface.co/datasets/mcp-tool-shop/jam-actions-v0)にもミラーリングされており、現在、**両方向の微調整結果**が含まれています。正直なネガティブな結果（v0）と、自身の勝利目標に1つだけ届かないものの、事前登録されたルールに従ったポジティブな結果（v1）です。詳細については、[微調整の結果](#training-dataset)を参照してください。このリリースでは、v1のパイプラインの実行ゲートが、公開されたウィンドウがBWV 846の実際の62小節を超過したことを検出し、バッハの楽曲のソースで修正（作業セットの修正r001/r002、誤り訂正）を行いました。MCPサーバー、インターフェース、データセットパッケージ、評価ハーネス、リリースゲートバリデーター全体で2506件のテストに合格しました。MIDIデータはすべて含まれており、すべての楽曲を使用して学習できます。また、その学習データセットも同梱されています。

## セキュリティとプライバシー

**アクセスされるデータ：** 楽曲ライブラリ（JSON + MIDI）、ユーザーの楽曲ディレクトリ（`~/.ai-jam-sessions/songs/`）、ギターのチューニング設定、練習日誌のエントリ、ローカルのオーディオ出力デバイス。

**アクセスされないデータ（デフォルトのパス）：** MCPサーバーとCLIは、ネットワークへの接続を行わず、認証情報を読み取らず、ユーザーの楽曲ディレクトリ外のシステムファイルにもアクセスしません。テレメトリーは収集または送信されません。同じパッケージに含まれる**（オプションの）データセット/評価ツール**（`scripts/run-llm-eval.ts`、プロベナンス検証ツール）は、唯一の例外です。明示的に起動した場合、LLM APIを呼び出すことができ（環境から`ANTHROPIC_API_KEY`を読み取りますが、保存することはありません）、プロベナンスURLを取得できます。これは、サーバー、CLI、またはインストールのいずれかのコンポーネントとして実行されることはありません。

**権限：** MCPサーバーは、stdioトランスポートのみを使用します（HTTPは使用しません）。CLIは、ローカルファイルシステムとオーディオデバイスにアクセスします。完全なポリシーについては、[SECURITY.md](SECURITY.md)を参照してください。
