# History rewrite: dry run and runbook

Dry run: 2026-09-25, on a throwaway mirror (`E:/AI/ai-jam-sessions-history-dryrun.git`, cloned from GitHub that day). **Nothing was pushed.** Every step below that changes GitHub is the owner's decision; this page makes that decision measurable. It is written against `derived-content-inventory.md`, which lists what the tree held.

## Standards compliance

| Standard | Score | Evidence |
|---|---|---|

| ANDON_AUTHORITY | 2 | Step 6 halts on any of: a scanner finding outside `kept-paths.txt`, a changed tip tree, a sealed-gate sha256 mismatch, a missing tag, or a red suite. |

## What the dry run measured

The mirror held 15 branches, 55 tags and 47 `refs/pull/*` refs: 1,217 commits in all. 817 of them are reachable from branches and tags. The other 382 are pre-purge twins of rewritten commits, reachable only through `refs/pull` since the 2026-09-09 MIDI purge.

Two passes were run on it:

1. **Path pass**: `--invert-paths` over 718 paths (`history-rewrite/remove-paths.txt`). The list has three parts:
   - 177 paths this PR deletes;
   - 435 paths that exist only in history and whose versions hold uncleared content. That covers the four works' records and piano rolls in the public package before 0.6.0 (116), the acoustic Träumerei records (36), Claude-written arrangements under `songs/builtin/` from 2026-02 (46), pre-reset `jam-actions-v1` and `-probe` records (228), and nine public-package eval traces;
   - 106 MIDI files purged on 2026-09-09 and still reachable through `refs/pull`.
2. **Content pass**: a `--file-info-callback` (`history-rewrite/drop-dirty-versions.py`) that turns every add or modify of a listed blob into a deletion. The list holds 119 flagged versions of 60 paths that still exist, 143 file changes in all (`history-rewrite/drop-blobs.txt`). Clean versions of those paths stay. This covers what a path filter cannot:
   - the public `records.jsonl` before 0.6.0, which held all 58 records of the four works;
   - older versions of the E-R items, the snapshot, the SFT data and the eval traces;
   - early versions of `README.md`, `src/smoke.ts` and `src/mcp-server.test.ts`.

## Owner decisions, before any step

1. **Scope.** You might expect the path pass to be enough; it removes every file this PR deletes and everything that exists only in history. It leaves the withdrawn records in every pre-0.6.0 version of the public `records.jsonl`, and every older version of the E-R items and the snapshot, which carry the in-copyright melodies. The content pass removes those. I recommend both passes. The extra cost is 36 more rewritten commits and two more moved tags, since nearly everything moves either way.
2. **Sealed gate sources.** You might expect the rewrite to take them too: three of the four hold traces of the withdrawn works (in all, 237 note units of single-pitch quiz options and tool results). I recommend keeping them (the default in `kept-paths.txt`). Removing them breaks `publish-jam-actions-v0.yml`, which would then need its history restore replaced. Keeping them costs three small historical files at one old tag.
3. **Amazing Grace.** The clock and receipts carry an uncleared arrangement's timing of a public-domain hymn. The published mp3s on GitHub Pages play its piano bed. They are held, not removed, in both the tree and this plan. Deciding to remove them means deleting the site audio and its landing-page section first; then drop their lines from `kept-paths.txt`.
4. **Order.** Merge the sweep PR first, then rewrite. The tip is then already clean, so the rewritten `main` has exactly the pre-rewrite tip tree, which step 6 checks. Rewriting first would delete the flagged tip versions, and the PR would then need rebasing onto a tree that lacks those files.

## Commands (steps 1-5)

Run from a checkout of `main` that includes the sweep (`$CHECKOUT`); the scanner reads song evidence from its `songs/`.

```bash
# 1. a fresh working mirror (never the backup)
WORK=/e/AI/ai-jam-sessions-rewrite-$DATE
git clone --mirror "$REPO" "$WORK/mirror.git"

# 2. what to remove, measured on this mirror
cd "$CHECKOUT"
pnpm exec tsx scripts/derived-content-scan.ts --history "$WORK/mirror.git" --json > "$WORK/history.json"
node -e '
const fs = require("fs");
const rows = JSON.parse(fs.readFileSync(process.argv[1], "utf8"));
const keep = new Set(fs.readFileSync("docs/findings/history-rewrite/kept-paths.txt", "utf8").split(/\r?\n/).filter((l) => l && !l.startsWith("#")));
const paths = rows.filter((r) => !r.presentAtHead && !keep.has(r.path)).map((r) => "literal:" + r.path);
const blobs = [...new Set(rows.filter((r) => r.presentAtHead && !keep.has(r.path)).flatMap((r) => r.dirtyBlobs))];
fs.writeFileSync(process.argv[2], paths.sort().join("\n") + "\n");
fs.writeFileSync(process.argv[3], blobs.sort().join("\n") + "\n");
' "$WORK/history.json" "$WORK/remove-paths.txt" "$WORK/drop-blobs.txt"
# the scanner skips binaries: add every historical MIDI path not at HEAD (the purged ones)
git -C "$WORK/mirror.git" log --all --name-only --format= -- '*.mid' | sort -u \
  | grep -v -x -F -f <(git -C "$WORK/mirror.git" ls-tree -r --name-only HEAD -- '*.mid') \
  | sed 's/^/literal:/' >> "$WORK/remove-paths.txt"
sort -u -o "$WORK/remove-paths.txt" "$WORK/remove-paths.txt"

# 3. compare with the dry run; review every added line before going on
#    (with core.autocrlf=true the committed lists check out as CRLF, hence tr)
diff <(tr -d '\r' < docs/findings/history-rewrite/remove-paths.txt | sort) "$WORK/remove-paths.txt"
diff <(tr -d '\r' < docs/findings/history-rewrite/drop-blobs.txt | sort) <(sort "$WORK/drop-blobs.txt")

# 4. path pass
cd "$WORK/mirror.git"
git filter-repo --invert-paths --paths-from-file "$WORK/remove-paths.txt"
cp -r filter-repo "$WORK/pass1"

# 5. content pass; its commit-map maps ORIGINAL ids to final ids (filter-repo chains runs)
DROP_BLOBS="$WORK/drop-blobs.txt" git filter-repo --force \
  --file-info-callback "$CHECKOUT/docs/findings/history-rewrite/drop-dirty-versions.py"
cp -r filter-repo "$WORK/pass2"
```

After the sweep merge, the 177 deletions are absent at HEAD, so step 2 lists them as history-only paths without special handling. The dry run built its path list from the PR's deletion list, because its mirror predated the merge.

## 7. Force-push order and tag re-creation

filter-repo removes the `origin` remote on purpose. Push only branches and tags, with explicit refspecs.

- **Never use `--mirror`.** It would try to rewrite the read-only `refs/pull/*` and delete remote branches missing from the mirror.
- **Branches before tags**, so no tag points into a history that `main` does not yet carry.
- **Releases** are bound to tag names and survive the tag update. That includes the draft `jam-ft-v1-adapters`.

```bash
cd "$WORK/mirror.git"
PROT=repos/mcp-tool-shop-org/ai-jam-sessions/branches/main/protection
# the protection read from the API on 2026-09-25, with only allow_force_pushes flipped
# for the window; re-read it first (gh api "$PROT") and stop if anything else differs
cat > "$WORK/protection-open.json" <<'JSON'
{"required_status_checks":{"strict":true,"checks":[{"context":"ci (22)","app_id":15368},{"context":"dep-audit","app_id":15368},{"context":"ci (24)","app_id":15368}]},"enforce_admins":false,"required_pull_request_reviews":null,"restrictions":null,"allow_force_pushes":true,"allow_deletions":false,"required_linear_history":false,"required_conversation_resolution":false,"lock_branch":false,"allow_fork_syncing":false}
JSON
sed 's/"allow_force_pushes":true/"allow_force_pushes":false/' "$WORK/protection-open.json" > "$WORK/protection-closed.json"
gh api -X PUT "$PROT" --input "$WORK/protection-open.json"
git push --force "$REPO" 'refs/heads/*:refs/heads/*'
git push --force "$REPO" 'refs/tags/*:refs/tags/*'
gh api -X PUT "$PROT" --input "$WORK/protection-closed.json"
```

Afterwards, check from outside: `git ls-remote "$REPO" 'refs/heads/*' 'refs/tags/*'` must equal the mirror's refs. Then clone branches and tags only (`git clone --bare`) and run check (a) on that clone. A full `--mirror` clone will still show old content through `refs/pull` until GitHub support acts.
